## Reproduced defects and corrections

**Workflow reviewer:** directory enumeration and workflow metadata errors could escape the promised JSON/exit-code interface. The file-size check preceded an unbounded `read_bytes()`, so a growing file could cause a larger allocation than the documented bound. Directory entries were materialized before the workflow-count rejection. Version 0.1.1 catches filesystem errors without printing exception content, uses an actual size-limited read, and streams enumeration with limits of 100 matching workflows and 1,000 total directory entries. The older read-permissions test also contained malformed YAML and now uses valid block-style syntax.

**Integrity verifier:** empty or incomplete manifests and duplicate entries could still produce PASS; malformed lines and subprocess timeouts could raise instead of producing a clean failure. Verification now checks canonical paths, duplicates, missing/unlisted artifacts, regular-file status and hashes, and handles failures explicitly. Local environment/cache files are excluded consistently with documented repository exclusions, not published or read as artifacts. Eleven verifier regressions cover these behaviors and valid/mismatch controls.

**Public presentation:** the README exposed current work, but the existing HTML did not link either current cybersecurity research or the workflow-review module. Its footer still said edition 03. Both public navigation paths are now present and the footer distinguishes archived edition 4.2 from current research maintenance. Four page regressions check links, edition, unique IDs/fragments and inline-script CSP hashes.

**Documentation:** the source register's blanket statement that all evidence was synthetic no longer covered the new, real advisory research. It now distinguishes the original synthetic teaching fixtures from attributed public advisories. PHP and Node.js references were rechecked; upstream discoveries remain credited upstream. The existing application statement records submission, not selection or an OpenAI endorsement.

## Unchanged boundaries and remaining limits

- Public GitHub content is separate from private working material. This audit does not change access to any private data store, repository permissions, application status or license.
- The workflow tool remains a textual heuristic reviewer, not a YAML semantic analyzer or production security sandbox. Concurrent adversarial filesystem mutation is not prevented atomically. No new CVE, zero-day or third-party compromise is claimed.
- The manifest is a consistency check, not an authenticated publisher signature. Tests are authored checks, not an independent security certification. Other Python versions and Windows were not executed in this run.
- Historical embedded downloads remain edition 4.2. Current security code is in the live repository; no historical bundle was silently rebuilt.
- External link availability and deployment are distinct from local tests. Publication should be checked by commit, branch and Pages deployment status; local success alone does not establish an anonymous visitor's experience.
